# 电商评论情感分类：标签质量、改进实验与工程化

> 数据集：online_shopping_10_cats（62,706 条，10 类）　模型：BERT-base-chinese　
> 测试集：9,406 条　硬件：RTX 3060 Laptop 6GB

---

## 摘要

本项目在中文电商评论二分类任务上，把 BERT 的测试集 Macro-F1 做到 **0.9466**（TF-IDF + LinearSVM 基线 0.9299）。
在此基础上对测试集全部 **502 条误判做了逐条人工审计**，结论是：

**标签噪声是「评测指标被低估」和「错误分析被扭曲」的主因，但不是「模型性能」的主因。**

- 502 条误判中 **246 条（49%）是原始标签写反**，而非模型判错。修正后同一模型的准确率从 0.9466 升到 **0.9728**——这 2.6 个百分点完全来自标签，与模型无关。
- 但反过来做训练集清洗（确认 137 条错标）与转折句增强（933 条过采样），整体提升 **+0.27 个百分点、p=0.125，不显著**。说明噪声并非当前模型的性能瓶颈。
- 模型真正的短板是**转折句**（92 例）与**长文本褒贬汇总**（115 例），这两类占真实模型错的 98%。

---

## 1. 业务问题

电商平台的负面评论识别，漏判一条真实差评（FN）的代价通常高于误报（FP）——差评没被捞出会直接影响售后响应与口碑预警。
因此评估不能只看 Accuracy，必须同时看**负面类 Recall**与**负面类 Precision**，并给出混淆矩阵。

## 2. 数据与划分

| split | 行数 | 负样本 | 正样本 | 负样本占比 |
|---|---|---|---|---|
| train | 43,893（去重去泄漏后） | 21,711 | 22,182 | 49.46% |
| val | 9,406 | 4,653 | 4,753 | 49.47% |
| test | 9,406 | 4,653 | 4,753 | 49.47% |

- 标签定义：**0 = 负面，1 = 正面**，全项目统一。
- 划分唯一来源：`outputs/predictions/{train,val,test}.csv`，由 `src/data_split.py` 统一校验（sha256 见 `outputs/experiments/split_manifest.json`）。
- 项目早期存在第二套划分（`train_baselines.py` 内部重新 `train_test_split`），导致 BERT 测试集有 1,850 条落在传统基线的训练/验证集里，已修复并归档至 `outputs/predictions/_deprecated_alt_split/`。
- 已知问题：train 与 test 有 1 条文本重复，两个训练脚本都会从训练集剔除。

## 3. 基线

| 模型 | Accuracy | Macro-F1 | 负面 Recall | 负面 Precision |
|---|---|---|---|---|
| TF-IDF + LogisticRegression | 0.9239 | 0.9239 | — | — |
| TF-IDF + NaiveBayes | 0.9253 | 0.9253 | — | — |
| TF-IDF + LinearSVM | 0.9299 | 0.9299 | 0.9329 | 0.9268 |
| **BERT-base-chinese** | **0.9466** | **0.9466** | 0.9443 | 0.9476 |

BERT 相对最强传统基线提升 1.7 个百分点。模型选择只依据验证集 Macro-F1（最佳 epoch=2），测试集仅最终评估一次。

## 4. 标签质量审计（核心工作）

### 4.1 方法

对测试集全部 502 条误判**逐条读原文**，人工打 5 类标签，并给出独立的真实情感判断（不看模型概率）。
判定结果分三类：**标签错**（模型对、标签反）、**模型错**（真错）、**双向存疑**（中性/跑题/乱码）。

### 4.2 结果

| 审计结论 | 条数 | 占比 |
|---|---|---|
| 标签错 | 246 | 49.0% |
| 模型错 | 211 | 42.0% |
| 双向存疑 | 45 | 9.0% |

误差方向**不对称**，这是最有信息量的发现：

| 方向 | 总数 | 其中标签错 | 其中真实模型错 |
|---|---|---|---|
| FN（标签正面、预测负面） | 243 | 163（67%） | 55 |
| FP（标签负面、预测正面） | 259 | 83（32%） | 156 |

- FN 侧三分之二是标签写反——模型其实抓对了那些差评，只是被算成"漏判"。
- FP 侧六成是真错——**模型存在系统性正面偏置**（真实 FP 156 vs 真实 FN 55），对褒贬参半的评论倾向于判正面。

### 4.3 对指标的影响

| 口径 | Accuracy | Macro-F1 | 负面 Recall | 负面 Precision |
|---|---|---|---|---|
| 原标签 | 0.9466 | 0.9466 | 0.9443 | 0.9476 |
| 人工复核后 | **0.9728** | **0.9728** | **0.9628** | 0.9827 |

**这 2.62 个百分点全部来自标签修正，模型没有任何改动**，不能用于宣称性能提升。
其价值在于：说明这份数据的"地板"比报告值低 2.6 个点，任何后续改进实验都必须在这个前提下解读。

### 4.4 噪声的形态

- 极性倒置（差评标正）：156 条；极性倒置（好评标负）：83 条；评价对象错位（评的是物流/赠品/价格却按商品标极性）：7 条。
- 集中在两类模板：**「好评打底 + 赠品/物流吐槽」**与**「差评 + 局部褒义」**。
- 独立佐证：`outputs/metrics/label_conflicts.csv` 有 36 条"同一文本、不同标签"的记录。

## 5. 改进实验（A → B → C → D）

每组只改一个因素，同一划分、同一种子 42、同一超参。

| 实验 | 改动 | Accuracy | Macro-F1 | 负面 Recall | 负面 Precision |
|---|---|---|---|---|---|
| A 原始 BERT | 对照 | 0.9466 | 0.9466 | 0.9443 | 0.9476 |
| B 训练集清洗 | 确认并翻转 137 条训练集错标（占 0.31%） | 0.9474 | 0.9474 | 0.9506 | 0.9435 |
| C 转折句过采样 | 933 条真转折样本 ×2（训练集 44,826 行） | 0.9486 | 0.9486 | 0.9482 | 0.9480 |
| **BC 组合** | B + C | **0.9493** | **0.9493** | **0.9508** | 0.9469 |
| D 方面级规则基线 | 8 个方面 + 权重聚合，不训练 | 0.6969 | 0.6817 | 0.4833 | 0.8342 |

**B 的清洗量为什么只有 137 条**：用否定感知规则筛出 365 条候选（`不好吃`/`不甜` 不算正面），逐条人工确认后只有 137 条真错标——规则精确率仅 29.7%（R2）/40.5%（R3），大部分"正词+负标签"其实是褒贬参半的混合评价。

**D 为什么失败**：规则基线 Macro-F1 0.6817，比 BERT 低 26 个百分点。且测试集 502 条误判里只有 3 条属于"评价对象不明确"，方面级对文档级准确率的理论提升空间本就很小。结论：**方面级不值得投入额外模型**，除非目标是可解释性而非准确率。

## 6. 显著性分析：为什么不能宣称"有效"

| 实验 | A 对 X 错 | A 错 X 对 | McNemar χ² | p | ΔAccuracy | 95% CI |
|---|---|---|---|---|---|---|
| B | 103 | 110 | 0.17 | 0.681 | +0.07pt | [−0.22, +0.37] |
| C | 104 | 123 | 1.43 | 0.232 | +0.20pt | [−0.11, +0.51] |
| BC | 110 | 135 | 2.35 | 0.125 | +0.27pt | [−0.04, +0.59] |

- 三组差值单调递增（B < C < BC），方向一致，但**没有一组通过显著性检验**，置信区间全部跨 0。
- n=9,406 时准确率的标准误约 0.23 个百分点；要稳定检出 0.27 个点的差异，需要约 10 万条测试样本。
- 更关键：**单 seed 微调的运行间方差通常 ±0.2~0.5 个百分点，大于所有观测差值**。因此严格讲，这四组在当前证据下无法区分。
- 佐证噪声存在的内部矛盾：BC 的验证集 Macro-F1（0.9491）低于 C（0.9519），测试集却更高。

### 6.1 唯一的稳健信号：平板类目

分类别配对检验（30 次比较，p<0.05 的期望假阳性约 1.5 个）：

| 实验 | 类别 | 样本数 | A 对 X 错 | A 错 X 对 | p |
|---|---|---|---|---|---|
| B | 平板 | 1,467 | 9 | 28 | 0.0031 |
| C | 平板 | 1,467 | 10 | 32 | 0.0012 |
| BC | 平板 | 1,467 | 7 | 36 | **<0.0001** |

平板类目 Macro-F1 从 0.9482 升到 0.9680，三次独立运行方向一致，不太可能是巧合。

### 6.2 但机制解释不成立

原本的假设是"清洗在标签噪声高的类目更有效"。**数据不支持**：

| 类别 | 标签错误率 | ΔMacro-F1（BC−A） |
|---|---|---|
| 平板 | 1.70%（倒数第二低） | **+1.98pt** |
| 蒙牛 | 1.59%（最低） | −0.95pt |
| 衣服 | 3.44% | +0.53pt |
| 水果 | 3.69%（最高） | −0.13pt |
| 洗发水 | 2.31% | −0.54pt |

噪声率与提升幅度的相关系数 **r = +0.28**（n=10），过采样比例与提升幅度 r = +0.34，都很弱（见 `figures/fig2_noise_vs_gain.png`）。

**因此不能把平板的改善归因于标签噪声。** 更可能的解释是平板文本短、模板化（大量"赠品/物流吐槽"句式），对清洗与过采样更敏感；但在没有进一步实验前，这仍只是假设。

## 7. 结论与局限

### 成立的结论

1. **标签噪声规模可观且可测量**：测试集 9,406 条中至少 246 条（2.6%）极性写反，修正后指标从 0.9466 升到 0.9728。
2. **噪声扭曲了错误分析**：502 条误判中 49% 是标签错。若不做审计直接按误判归因，会把一半的"模型缺点"错算成模型问题。
3. **模型真实短板是转折句与长文本汇总**：211 条真错中，转折或反讽 92 条、语义理解（多为长文本褒贬汇总）115 条。
4. **模型存在正面偏置**：真实 FP 156 vs 真实 FN 55。
5. **方面级规则路线不可行**：Macro-F1 0.6817，且理论提升空间仅 3 条样本。

### 不成立的结论（必须写明）

1. **不能说清洗或增强提升了模型**：+0.27pt、p=0.125，且单 seed 方差大于效应量。
2. **不能说"清洗在噪声高的类目更有效"**：相关系数仅 0.28，且有多个反例。
3. **不能把平板类目的改善当作通用结论**：单类目、机制未明，需多 seed 验证。

### 局限

- 只审计了误判样本（502 条），正确分类的 8,904 条未审计，真实噪声率可能高于 2.6%。
- 训练集只做了规则筛查（365 候选），未做全量随机抽样审计，噪声率无无偏估计。
- 每组实验单 seed，未做多次重复。
- 分类别检验属探索性分析，存在多重比较问题。

## 8. 复现

```bash
# 环境
conda activate ml311          # Python 3.11 + torch 2.6 + transformers 5.20
export HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1

# 1. 校验划分
python src/verify_split_unified.py

# 2. 训练基线（A）
python src/train_bert.py

# 3. 标签清洗（B）
python src/train_bert.py --run-tag B_clean_train \
  --label-fixes outputs/experiments/stage3/label_fixes_train.csv --allow-split train

# 4. 转折句过采样（C）
python src/train_bert.py --run-tag C_contrastive \
  --augment-file outputs/experiments/stage3/contrastive_oversample.csv

# 5. 组合（BC）
python src/train_bert.py --run-tag BC_clean_contrastive \
  --label-fixes outputs/experiments/stage3/label_fixes_train.csv --allow-split train \
  --augment-file outputs/experiments/stage3/contrastive_oversample.csv

# 6. 汇总与图表
python src/stage3_report.py
python src/make_figures.py

# 7. API
uvicorn src.api:app --port 8000
python -m pytest tests/test_api.py -q
```
